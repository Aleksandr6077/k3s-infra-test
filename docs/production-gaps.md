## 🏛 Пять столпов Production (Стратегический аудит)
*Сейчас проект закрывает инструментарий (IaC, GitOps, CI), но не хватает глубины эксплуатации.*

### 🔥 1. Безопасность и Доступы (Критично для нашего стенда)
- **Проблема:** Работа под `admin-kubeconfig`, нет ограничений для подов (SecurityContext), нет RBAC-ролей.
- **Что делать:**
  - Внедрить `runAsNonRoot: true` и `readOnlyRootFilesystem` в манифесты Nginx и Loki.
  - Создать отдельный ServiceAccount и Role для ArgoCD с минимальными правами.
  - Настроить NetworkPolicy (запретить всё, кроме DNS и явных портов).

### 🛡 2. Сеть и Маршрутизация (Следующий шаг архитектуры)
- **Проблема:** Flannel CNI без NetworkPolicy, нет TLS-сертификатов (cert-manager).
- **Что делать:**
  - Установить `cert-manager` через ArgoCD и выпустить сертификаты Let's Encrypt для Nginx/Loki (через Traefik).
  - Перейти с Flannel на Calico или Cilium (только если планируем strict NetworkPolicy).

### 💾 3. Хранение и Stateful (Понимание баз данных)
- **Проблема:** Нет реальной БД (PostgreSQL) с тестами восстановления.
- **Что делать:**
  - Добавить CloudNativePG (PostgreSQL) в App of Apps.
  - Настроить ежедневные бэкапы в Yandex Object Storage (S3) через Barman.
  - Провести тест: `make down` -> `make up` -> восстановление БД из бэкапа.

### 📊 4. Наблюдаемость (Прикладные метрики и SLO)
- **Проблема:** Стек есть, скелет есть - но алерты не работают (Telegram молчит, нужно дебажить), нет RED/USE метрик для Nginx, нет трейсинга.
- **Что делать:**
  - Настроить Alertmanager (проверить, что Telegram-алерты реально доходят).
  - Добавить `ServiceMonitor` для Nginx (чтобы Prometheus собирал метрики с приложения).
  - Внедрить distributed tracing (Tempo или Jaeger) для Nginx.

### 🐧 5. ОС и Ядро Linux (Глубокая настройка)
- **Проблема:** K3s ставится «скриптом», не настроены sysctl, лимиты, OOM-killer.
- **Что делать:**
  - Добавить в Ansible-роль `local_env` или `k3s` настройку `sysctl` (например, `vm.max_map_count` для Loki и `net.ipv4.ip_forward`).
  - Настроить `systemd` лимиты для kubelet (чтобы K3s не съедал всю память при OOM).

---
*Приоритет: 1 и 4 (Безопасность и Наблюдаемость) — делать параллельно с текущими задачами. 2 и 3 — после стабилизации Loki/Grafana. 5 — при переходе на выделенные ВМ.*
